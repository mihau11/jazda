# Tankette Commander — Milestones

See `DESIGN.md` for the full design rationale behind each item below.

1. **[DONE] Toolchain & window** — Confirm GNAT + an Ada SDL2 binding (e.g. SDLAda) can open a window and blit a raw framebuffer from Ada. No gameplay; just proves the pipeline.
   - Built on GNAT 14.2.0 + gprbuild inside WSL (Debian), rendering via WSLg. Used a thin hand-written `Interfaces.C` binding (`src/sdl2_thin.ads/.adb`) against the system `libSDL2-2.0.so.0`, rather than pulling in Alire/a third-party binding.
   - `src/main.adb` opens a window, uploads a 320x200 ARGB8888 framebuffer to a streaming texture every frame, and quits cleanly on window-close or Esc.
   - Verified live: window opened, responded to real mouse input, closed normally — see `tankette.gpr` for the build (`gprbuild -P tankette.gpr` from WSL, run `bin/main`).
2. **[DONE] Raycasting prototype** — Static test map, single fixed wide-FOV camera, walls only. No player input yet.
   - Grid-DDA raycaster (`src/raycaster.ads/.adb`), Lodev-style: one ray per screen column, perpendicular-distance correction (no fisheye), side-shading (X-side walls lighter than Y-side) for depth cues.
   - Static test level (`src/world_map.ads/.adb`): bordered room, an enclosed inner chamber, a lone pillar, and a barrier wall with corridor gaps — chosen to exercise corners, isolated columns, and long flat walls.
   - Camera position is fixed; facing angle auto-rotates each frame (no input wired up yet) so the projection could be checked across a full sweep of angles.
   - `src/framebuffer.ads` factored out as the shared pixel-buffer type/dimensions used by both `main.adb` and `Raycaster`.
   - Verified live: window showed the rotating test room, closed manually — confirms the DDA math, distance shading, and per-frame render-to-texture path all work together.
3. **[DONE] View mode switching** — Implement periscope (wide FOV) vs gun sight (narrow FOV/zoom) toggle on **Z**, plus the azimuth HUD element.
   - `src/view.ads/.adb`: `View.Mode` (Periscope/Gun_Sight) and per-mode camera-plane length (FOV); toggled edge-triggered on **z** (`src/sdl2_thin.ads/.adb` gained `SDLK_Z` and a `Key_Repeat` check so holding the key doesn't re-toggle).
   - `src/hud.adb`: header bar with a plain 3-digit azimuth readout (0=north, 90=east, clockwise) via a small hand-rolled 3x5 pixel digit font (`Digit_Glyphs`) — replaced an earlier compass-ring design per feedback. Direction of increase matched to the user's expectation after one flip.
   - Gun-sight mode adds a circular scope-tube vignette (masks the rectangular render to a round sight picture, radius tuned live to 80px) and a Mauser-style post reticle (thin horizontal wire + thick post rising from below into center, forming a "T") in place of a plain crosshair.
   - Verified live over several iterations: azimuth number, zoom toggle, vignette circle size, and reticle shape all checked visually and adjusted per feedback.
4. **[DONE] Gun aiming** — Arrow-key gun rotation, independent of hull facing; sensitivity toggle on **X**.
   - `src/gun.ads/.adb`: gun `State` (angle, elevation, sensitivity tier) and fine-aim turn/elevation rates per tier, cycled by **X** (`SDLK_X` added to `sdl2_thin`).
   - Continuous held-key input via `SDL_GetKeyboardState` (new binding in `sdl2_thin.ads/.adb`, scancode-indexed) rather than discrete events — arrow keys and I/J/K/L (`SC_I/J/K/L`) both read every frame.
   - Evolved through feedback into the final scheme: periscope panning added (arrows now also pan the periscope, not just the gun) with its own independent angle; gun aiming rebound from arrows-only to **I/J/K/L** (J/L traverse, I/K elevate) at a much lower, precise sensitivity; then unified so **both** arrows (coarse) and I/J/K/L (fine) work in **both** view modes — whichever sight is on screen is what traverses, elevation always targets the gun. Gun-sight controls tuned down to quarter speed relative to the periscope.
   - `Raycaster.Render` gained a `Horizon_Shift` parameter (y-shear pitch) so gun elevation tilts the Gun_Sight picture only; periscope stays level.
   - Verified live over several iterations: independent periscope/gun panning, elevation persisting across mode switches, sensitivity cycling, and the coarse/fine/quarter-speed feel all checked interactively and adjusted per feedback.
5. **[DONE] Track-declutch drive model** — Engine/track state machine; hull rotation comes from differential track power, not direct turn input; hull facing drives the raycasting camera separately from gun direction.
   - `src/hull.ads/.adb`: `Hull.State` (X/Y/Angle) with a two-track differential-drive model — each track's speed is the throttle speed unless declutched (then zero, clutch-brake style); `Linear_Speed = (Left+Right)/2`, `Angular_Speed = (Right-Left)/Track_Base` combine them. Simple axis-separated collision against `World_Map.Cell` (small clearance radius) lets the hull slide along walls instead of stopping dead or clipping through.
   - Controls: **Q**/**E** declutch the right/left track (turning comes only from the resulting differential), **Space**/**C** throttle forward/reverse (`SC_Q/E/SPACE/C` added to `sdl2_thin`). Q/E swapped once from the initial mapping per feedback.
   - Periscope pan and gun traverse (`Periscope_Angle`/`Gun_State.Angle`) are now offsets added to `Hull_State.Angle` — turning the hull carries the view/aim along, matching a periscope/turret actually bolted to the tank, while panning/traversing still works independently on top of that.
   - Added beyond the original scope, per feedback: a hull-relative HUD indicator next to the azimuth number (`Hud.Draw_Hull_Icon`) — a small rectangle for the hull with a red line showing the current periscope/gun offset from dead-ahead; and a limited gun traverse arc (`Gun.Max_Traverse`, tuned live to **7 degrees** either side of hull-forward — this fictional tankette's mount isn't a full 360 turret).
   - Verified live over several iterations: throttle, Q/E turn direction (swapped once), wall collision, hull-relative view sweep, the hull-icon indicator, and the traverse limit all checked interactively and adjusted per feedback.
   - Added beyond scope: a binocular vignette for the periscope view (`Hud.Draw`, two overlapping circles masking the render, mirroring the gun-sight's single-circle scope vignette) — confirmed live.
6. **[DONE, hit-precision tuning open] World entities & combat** — Placeable infantry and AT-gun entities; MG and autocannon firing; hit detection against them.
   - `src/entities.ads`: fixed test placement (two `Infantry`, one `AT_Gun`) in the milestone-2 room's open cells.
   - `src/raycaster.ads/.adb`: billboard sprite pass (`Render_Entities`), depth-tested against a new per-column `Depth_Buffer` populated by `Render`, so sprites are properly occluded by nearer walls (and the pillar).
   - `src/combat.ads/.adb`: hitscan `Fire` along the gun's current laid world direction (hull + gun offset, regardless of which sight is on screen — the coax shares the main gun's axis), stepped against `World_Map` (stops at a wall) and `Entities.List` (per-entity hit radius). `Machine_Gun` only affects `Infantry`; `Autocannon` affects either.
   - Controls evolved per feedback from mouse clicks to keyboard: **s** fires the machine gun, **a**+**s** fires the autocannon (checked as a modifier at the moment **s** is pressed, via `SDL_GetKeyboardState`) — the now-unused mouse-button binding was removed from `sdl2_thin`.
   - Hit radius tuned down twice per feedback (a radius matched to half the sprite's visual width still let a couple of degrees of aim error register as a hit, since the hit cone widens with range): `Infantry` 0.35 → 0.18 → **0.08**, `AT_Gun` 0.35 → **0.15**. Still feels slightly forgiving per last check — left open for further tuning, not blocking.
   - Verified live over several iterations: sprite rendering/occlusion, S/A+S firing, and hit precision all checked interactively; hit precision explicitly flagged as good-enough-for-now rather than fully resolved.
7. **[DONE] Player lethality model** — Proximity-triggered instant kill from close infantry; 3-hits-then-destroyed logic for AT guns.
   - Infantry: any alive `Infantry` entity within point-blank range (`Proximity_Kill_Radius` = 1.0) of the hull destroys the tank instantly (checked every frame in `main.adb`, guarded by `Player_Alive`).
   - `src/at_gun_ai.ads/.adb`: each alive `AT_Gun` needs `Aim_Time` (3s) of continuous line of sight (`Combat.Has_Line_Of_Sight`, a wall-marching check reusing `Combat`'s step size) before its first shot; once locked on, it fires again every `Reload_Time` (tuned live from 3s to **5s**) for as long as sight holds, no repeat aim delay — losing sight at any point resets it back to needing a fresh `Aim_Time` acquisition. Originally built as symmetric 3s-aim/3s-reload alternating phases; simplified per feedback to "aim once, then just reload" since re-aiming an already-tracked target didn't make sense.
   - Player absorbs `Max_AT_Hits` = 3 AT hits; the 4th (`Player_Hits_Taken > Max_AT_Hits`) destroys the tank.
   - Either death freezes controls (event handlers and the movement/aiming block gated on `Player_Alive`) and fills the screen solid red (`Destroyed_Color`).
   - Added per feedback (hit feedback was originally undiscoverable — a kill took up to ~24s of continuous exposure with no interim cue): `Hud.Draw_Hit_Pips` (3 boxes in the header, filling red per hit taken) and `Hud.Apply_Flash` (a brief whole-screen color blend on non-fatal hits).
   - Verified live over several iterations: infantry proximity kill, the full AT-gun aim/fire/reload/kill sequence, hit pips, and the flash cue all checked interactively; reload timing tuned twice per feedback.
8. **[DONE] Radio report system** — Spawn-detection triggers generate the text report log/queue: once per entity, at the moment it spawns into the world (not when the player spots it), a report is generated with the bearing from the player's position at that moment (same compass convention as the HUD azimuth).
   - `src/entities.ads` gained a `Reported : Boolean` flag per entity; `src/radio.ads/.adb` (`Radio.Check_Spawns`) scans `Entities.List` every frame and, the first time it sees an alive, not-yet-reported entity, queues a message and marks it reported — currently that means all fixed test entities get queued on the very first frame, since there's no dynamic mid-mission spawning yet (that's milestone 9's job).
   - Each message is built from a kind string ("INFANTRY SQUAD SPOTTED AT " / "AT GUN SPOTTED AT ") plus a 3-digit bearing computed by `Radio.Bearing_Deg`, reusing the same "north = +Y, clockwise" convention as the HUD azimuth number.
   - `Radio.Update` pops the queue into a `Current` message on a `Display_Duration` (4s) timer; `main.adb` calls `Check_Spawns`/`Update` every frame and, when `Radio.Has_Message`, draws it via a new `Hud.Draw_Banner` (bottom-of-screen text band).
   - `Hud`'s pixel font (previously digits-only, from milestone 3's azimuth readout) was extended with a full `Letter_Glyph` table covering every letter the two message templates need.
   - Verified via a clean `gprbuild -P tankette.gpr -f -p` (no warnings under `-gnatwa`) and a runtime smoke run (`bin/main` stayed up under WSLg for the duration of a timed run with no crash/error output). This was executed as a background job without an interactive session, so — unlike prior milestones — the banner's on-screen appearance, text legibility, and timing haven't been eyeballed live yet; worth a quick visual pass before moving on.
9. **Mission structure** — Bounded map, contact list to resolve, mission end state (loss on destruction; win condition TBD — revisit the open question in DESIGN.md). Includes a pre-game custom map editor: before the mission starts, the player picks the map size and places obstacles/entities on a simple top-down 2D grid screen (arrow keys move a cursor, number keys stamp wall/pillar/barrier/infantry/AT-gun), reusing the pixel-drawing/digit-font primitives already built for the HUD rather than the 3D raycasting view. Requires `World_Map`/`Entities` to move from compile-time-constant fixed-size arrays to runtime-sized ones (a fixed max-size buffer with actual width/height tracked separately, not true dynamic arrays).
10. **Minimal audio & feel pass** — Engine sound tied to track/RPM state, gunfire, radio chatter cue; final minimalist art pass.
