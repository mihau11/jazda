# Tankette Commander — Milestones

See `DESIGN.md` for the full design rationale behind each item below.

1. **[DONE] Toolchain & window** — Confirm GNAT + an Ada SDL2 binding (e.g. SDLAda) can open a window and blit a raw framebuffer from Ada. No gameplay; just proves the pipeline.
   - Built on GNAT 14.2.0 + gprbuild inside WSL (Debian), rendering via WSLg. Used a thin hand-written `Interfaces.C` binding (`src/sdl2_thin.ads/.adb`) against the system `libSDL2-2.0.so.0`, rather than pulling in Alire/a third-party binding.
   - `src/main.adb` opens a window, uploads a 320x200 ARGB8888 framebuffer to a streaming texture every frame, and quits cleanly on window-close or Esc.
   - Verified live: window opened, responded to real mouse input, closed normally — see `tankette.gpr` for the build (`gprbuild -P tankette.gpr` from WSL, run `bin/main`).
2. **[DONE] Raycasting prototype** — Static test map, single fixed wide-FOV camera, walls only. No player input yet.
   - Grid-DDA raycaster (`src/raycaster.ads/.adb`), Lodev-style: one ray per screen column, perpendicular-distance correction (no fisheye), side-shading (X-side walls lighter than Y-side) for depth cues.
   - Static test level (`src/world_map.ads/.adb`): bordered room, an enclosed inner chamber, a lone pillar, and a barrier wall with corridor gaps — chosen to exercise corners, isolated columns, and long flat walls.
   - Camera position is fixed; facing angle auto-rotates each frame (no input wired up yet) so the projection could be checked across a full sweep of angles.
   - `src/framebuffer.ads` factored out as the shared pixel-buffer type/dimensions used by both `main.adb` and `Raycaster`.
   - Verified live: window showed the rotating test room, closed manually — confirms the DDA math, distance shading, and per-frame render-to-texture path all work together.
3. **[DONE] View mode switching** — Implement periscope (wide FOV) vs gun sight (narrow FOV/zoom) toggle on **Z**, plus the azimuth HUD element.
   - `src/view.ads/.adb`: `View.Mode` (Periscope/Gun_Sight) and per-mode camera-plane length (FOV); toggled edge-triggered on **z** (`src/sdl2_thin.ads/.adb` gained `SDLK_Z` and a `Key_Repeat` check so holding the key doesn't re-toggle).
   - `src/hud.adb`: header bar with a plain 3-digit azimuth readout (0=north, 90=east, clockwise) via a small hand-rolled 3x5 pixel digit font (`Digit_Glyphs`) — replaced an earlier compass-ring design per feedback. Direction of increase matched to the user's expectation after one flip.
   - Gun-sight mode adds a circular scope-tube vignette (masks the rectangular render to a round sight picture, radius tuned live to 80px) and a Mauser-style post reticle (thin horizontal wire + thick post rising from below into center, forming a "T") in place of a plain crosshair.
   - Verified live over several iterations: azimuth number, zoom toggle, vignette circle size, and reticle shape all checked visually and adjusted per feedback.
4. **[DONE] Gun aiming** — Arrow-key gun rotation, independent of hull facing; sensitivity toggle on **X**.
   - `src/gun.ads/.adb`: gun `State` (angle, elevation, sensitivity tier) and fine-aim turn/elevation rates per tier, cycled by **X** (`SDLK_X` added to `sdl2_thin`).
   - Continuous held-key input via `SDL_GetKeyboardState` (new binding in `sdl2_thin.ads/.adb`, scancode-indexed) rather than discrete events — arrow keys and I/J/K/L (`SC_I/J/K/L`) both read every frame.
   - Evolved through feedback into the final scheme: periscope panning added (arrows now also pan the periscope, not just the gun) with its own independent angle; gun aiming rebound from arrows-only to **I/J/K/L** (J/L traverse, I/K elevate) at a much lower, precise sensitivity; then unified so **both** arrows (coarse) and I/J/K/L (fine) work in **both** view modes — whichever sight is on screen is what traverses, elevation always targets the gun. Gun-sight controls tuned down to quarter speed relative to the periscope.
   - `Raycaster.Render` gained a `Horizon_Shift` parameter (y-shear pitch) so gun elevation tilts the Gun_Sight picture only; periscope stays level.
   - Verified live over several iterations: independent periscope/gun panning, elevation persisting across mode switches, sensitivity cycling, and the coarse/fine/quarter-speed feel all checked interactively and adjusted per feedback.
5. **[DONE] Track-declutch drive model** — Engine/track state machine; hull rotation comes from differential track power, not direct turn input; hull facing drives the raycasting camera separately from gun direction.
   - `src/hull.ads/.adb`: `Hull.State` (X/Y/Angle) with a two-track differential-drive model — each track's speed is the throttle speed unless declutched (then zero, clutch-brake style); `Linear_Speed = (Left+Right)/2`, `Angular_Speed = (Right-Left)/Track_Base` combine them. Simple axis-separated collision against `World_Map.Cell` (small clearance radius) lets the hull slide along walls instead of stopping dead or clipping through.
   - Controls: **Q**/**E** declutch the right/left track (turning comes only from the resulting differential), **Space**/**C** throttle forward/reverse (`SC_Q/E/SPACE/C` added to `sdl2_thin`). Q/E swapped once from the initial mapping per feedback.
   - Periscope pan and gun traverse (`Periscope_Angle`/`Gun_State.Angle`) are now offsets added to `Hull_State.Angle` — turning the hull carries the view/aim along, matching a periscope/turret actually bolted to the tank, while panning/traversing still works independently on top of that.
   - Added beyond the original scope, per feedback: a hull-relative HUD indicator next to the azimuth number (`Hud.Draw_Hull_Icon`) — a small rectangle for the hull with a red line showing the current periscope/gun offset from dead-ahead; and a limited gun traverse arc (`Gun.Max_Traverse`, tuned live to **7 degrees** either side of hull-forward — this fictional tankette's mount isn't a full 360 turret).
   - Verified live over several iterations: throttle, Q/E turn direction (swapped once), wall collision, hull-relative view sweep, the hull-icon indicator, and the traverse limit all checked interactively and adjusted per feedback.
   - Added beyond scope: a binocular vignette for the periscope view (`Hud.Draw`, two overlapping circles masking the render, mirroring the gun-sight's single-circle scope vignette) — confirmed live.
6. **[DONE, hit-precision tuning open] World entities & combat** — Placeable infantry and AT-gun entities; MG and autocannon firing; hit detection against them.
   - `src/entities.ads`: fixed test placement (two `Infantry`, one `AT_Gun`) in the milestone-2 room's open cells.
   - `src/raycaster.ads/.adb`: billboard sprite pass (`Render_Entities`), depth-tested against a new per-column `Depth_Buffer` populated by `Render`, so sprites are properly occluded by nearer walls (and the pillar).
   - `src/combat.ads/.adb`: hitscan `Fire` along the gun's current laid world direction (hull + gun offset, regardless of which sight is on screen — the coax shares the main gun's axis), stepped against `World_Map` (stops at a wall) and `Entities.List` (per-entity hit radius). `Machine_Gun` only affects `Infantry`; `Autocannon` affects either.
   - Controls evolved per feedback from mouse clicks to keyboard: **s** fires the machine gun, **a**+**s** fires the autocannon (checked as a modifier at the moment **s** is pressed, via `SDL_GetKeyboardState`) — the now-unused mouse-button binding was removed from `sdl2_thin`.
   - Hit radius tuned down twice per feedback (a radius matched to half the sprite's visual width still let a couple of degrees of aim error register as a hit, since the hit cone widens with range): `Infantry` 0.35 → 0.18 → **0.08**, `AT_Gun` 0.35 → **0.15**. Still feels slightly forgiving per last check — left open for further tuning, not blocking.
   - Verified live over several iterations: sprite rendering/occlusion, S/A+S firing, and hit precision all checked interactively; hit precision explicitly flagged as good-enough-for-now rather than fully resolved.
7. **[DONE] Player lethality model** — Proximity-triggered instant kill from close infantry; 3-hits-then-destroyed logic for AT guns.
   - Infantry: any alive `Infantry` entity within point-blank range (`Proximity_Kill_Radius` = 1.0) of the hull destroys the tank instantly (checked every frame in `main.adb`, guarded by `Player_Alive`).
   - `src/at_gun_ai.ads/.adb`: each alive `AT_Gun` needs `Aim_Time` (3s) of continuous line of sight (`Combat.Has_Line_Of_Sight`, a wall-marching check reusing `Combat`'s step size) before its first shot; once locked on, it fires again every `Reload_Time` (tuned live from 3s to **5s**) for as long as sight holds, no repeat aim delay — losing sight at any point resets it back to needing a fresh `Aim_Time` acquisition. Originally built as symmetric 3s-aim/3s-reload alternating phases; simplified per feedback to "aim once, then just reload" since re-aiming an already-tracked target didn't make sense.
   - Player absorbs `Max_AT_Hits` = 3 AT hits; the 4th (`Player_Hits_Taken > Max_AT_Hits`) destroys the tank.
   - Either death freezes controls (event handlers and the movement/aiming block gated on `Player_Alive`) and fills the screen solid red (`Destroyed_Color`).
   - Added per feedback (hit feedback was originally undiscoverable — a kill took up to ~24s of continuous exposure with no interim cue): `Hud.Draw_Hit_Pips` (3 boxes in the header, filling red per hit taken) and `Hud.Apply_Flash` (a brief whole-screen color blend on non-fatal hits).
   - Verified live over several iterations: infantry proximity kill, the full AT-gun aim/fire/reload/kill sequence, hit pips, and the flash cue all checked interactively; reload timing tuned twice per feedback.
   - `Proximity_Kill_Radius` widened from 1.0 to 1.5 per feedback, now that infantry actually close distance (see below) rather than only mattering if the player wandered into a stationary squad.
   - Added post-milestone-10 per feedback: infantry were static until the player wandered into `Proximity_Kill_Radius`, which made the point-blank threat toothless on any map with room to avoid them. New `src/infantry_ai.ads/.adb` (`Infantry_Ai.Update`, called each frame from `main.adb` alongside `At_Gun_Ai.Update`) advances every alive `Infantry` entity toward the player's current position each frame at a slow walking pace (`Speed` = 0.6 world units/sec, well under the tank's own throttle speed), sliding along `World_Map` walls on whichever axis is open rather than stopping dead or clipping through -- same technique as `Hull.Update`. No pathfinding: a squad blocked by a wall with no direct line to the player just pushes against it, consistent with this project's minimalist AI elsewhere (`At_Gun_Ai` is similarly LOS-only, no navigation). AT guns are stationary emplacements and are unaffected.
8. **[DONE] Radio report system** — Spawn-detection triggers generate the text report log/queue: once per entity, at the moment it spawns into the world (not when the player spots it), a report is generated with the bearing from the player's position at that moment (same compass convention as the HUD azimuth).
   - `src/entities.ads` gained a `Reported : Boolean` flag per entity; `src/radio.ads/.adb` (`Radio.Check_Spawns`) scans `Entities.List` every frame and, the first time it sees an alive, not-yet-reported entity, queues a message and marks it reported — currently that means all fixed test entities get queued on the very first frame, since there's no dynamic mid-mission spawning yet (that's milestone 9's job).
   - Each message is built from a kind string ("INFANTRY SQUAD SPOTTED AT " / "AT GUN SPOTTED AT ") plus a 3-digit bearing computed by `Radio.Bearing_Deg`, reusing the same "north = +Y, clockwise" convention as the HUD azimuth number.
   - `Radio.Update` pops the queue into a `Current` message on a `Display_Duration` (4s) timer; `main.adb` calls `Check_Spawns`/`Update` every frame and, when `Radio.Has_Message`, draws it via a new `Hud.Draw_Banner` (bottom-of-screen text band).
   - `Hud`'s pixel font (previously digits-only, from milestone 3's azimuth readout) was extended with a full `Letter_Glyph` table covering every letter the two message templates need.
   - Verified via a clean `gprbuild -P tankette.gpr -f -p` (no warnings under `-gnatwa`) and a runtime smoke run (`bin/main` stayed up under WSLg for the duration of a timed run with no crash/error output). This was executed as a background job without an interactive session, so — unlike prior milestones — the banner's on-screen appearance, text legibility, and timing haven't been eyeballed live yet; worth a quick visual pass before moving on.

Includes a pre-game custom map editor: before the mission starts, the player picks the map size and places obstacles/entities on a simple top-down 2D grid screen (arrow keys move a cursor, number keys stamp wall/pillar/barrier/infantry/AT-gun), reusing the pixel-drawing/digit-font primitives already built for the HUD rather than the 3D raycasting view.    - Resolved DESIGN.md's open win/loss question: win = every mission-quota contact spawned and destroyed (contact list fully resolved); time-limit/extraction-point alternatives considered but not chosen.
   - Verified via a clean `gprbuild -P tankette.gpr -f -p` (no warnings under `-gnatwa`) and a runtime smoke run (`bin/main` stayed up under WSLg for a timed run with no crash/error output), plus a manual code-path review of the new bounds/clamping logic (map resize, cursor movement, random spawn placement). 10. **[DONE] Minimal audio & feel pass** — Engine sound tied to track/RPM state, gunfire, radio chatter cue; final minimalist art pass.
    - The codebase has no external assets of any kind (no images, no sound files) -- everything is procedurally drawn. To stay consistent with that, rather than pull in SDL2_mixer or ship .wav files, `src/audio.ads/.adb` synthesizes every sound at runtime (square/sine tones plus a cheap LCG noise generator) and pushes samples straight to a raw SDL2 audio device via `SDL_QueueAudio`. `src/sdl2_thin.ads` gained the matching bindings (`Audio_Spec`, `SDL_OpenAudioDevice`, `SDL_QueueAudio`, etc.) -- struct layout and constants were verified against the real build toolchain (`sizeof(SDL_AudioSpec) == 32` on x86_64 Linux/WSL) before writing the Ada side.
    - A continuous engine drone (`Audio.Update`) tracks a smoothed `Engine_RPM` in `main.adb` derived from throttle state, pitching up under power; a detuned overtone mixes in while a track is declutched under power (`Track_Strain`), for a grinding cue distinct from a clean idle. Player gunfire (`Audio.Play_Gunfire`), the enemy AT gun's own bark (`Audio.Play_At_Gun_Fire`, added per feedback -- milestone text said "gunfire" without specifying whose), and a two-tone radio chatter cue (`Audio.Play_Radio_Blip`, triggered on the false-to-true edge of `Radio.Has_Message`) are independent one-shot channels mixed on top of the drone, so they can overlap without stepping on each other.
    - Added per the user's explicit request beyond the milestone text: a muzzle-flash blink on firing. `Hud.Apply_Flash` (previously hardcoded to the red hit-taken color) was refactored into a shared `Apply_Color_Flash` helper plus two thin wrappers, so the new `Hud.Apply_Muzzle_Flash` reuses the same blend math toward a distinct warm/bright color, driven by a much shorter timer (0.06s vs. the hit flash's 0.25s) so it reads as a quick blink rather than a wash.
    - "Final minimalist art pass" was scoped down with the user to a light color/contrast check rather than new visual elements, given there is no art brief to work from in a procedurally-drawn game. A live WSLg screenshot of the periscope HUD (azimuth readout, hull icon, binocular vignette) showed the existing palette already reads cleanly; the only change made was giving the new muzzle flash its own color distinct from the existing red hit-flash.
    - Tuned twice per live feedback after the first pass: (1) audible latency -- `Audio.Update` originally queued a fixed Dt worth of audio every frame behind a generous 8000-byte (~180ms) backlog cap, and the SDL device itself asked for a 1024-sample (~46ms) hardware period; both were sized for safety margin, not latency, and it showed. Replaced the whole approach with a top-up model: each call tops the device's queue up to a small fixed `Target_Queue_Bytes` (~40ms) rather than blindly appending per-frame, and the hardware period dropped to 256 samples (~12ms, verified this exact size is honored by the real backend before committing to it) -- Dt is no longer needed at all as an `Audio.Update` parameter, since the top-up target self-corrects every call regardless of frame timing. (2) The muzzle-flash blink was reportedly not clearly visible while looking through either sight -- turned out to be a compositing-order issue, not contrast: it was applied after `Hud.Draw`, so it bled across the vignette's own black mask (the binocular/scope-tube surround) instead of staying confined to the visible sight picture. Moved the `Apply_Muzzle_Flash` call to before `Hud.Draw` so the vignette mask paints on top of it -- a light from the player's own gun belongs on the raw scene, not on the eyepiece housing. `Apply_Flash` (hit-taken) deliberately stays after `Hud.Draw` and full-screen, since that one is a UI jolt cue rather than a light in the world. Also bumped `Muzzle_Color` to a more saturated flash-orange and `Muzzle_Flash_Duration` to 0.10s while investigating, which stand on their own regardless of the ordering fix.
    - Verified via a clean `gprbuild -P tankette.gpr -f -p` (no warnings under `-gnatwa`) and a live WSLg smoke run: drove through the map editor into `Playing`, confirmed `Audio.Init` opens a real device in this environment (pulseaudio / RDP sink), fired both weapons, and screenshotted the running periscope view to confirm no HUD regression. As with milestones 8/9, this ran as a background job -- the actual audio mix (tone balance, whether the engine drone sits at a good volume under gunfire, whether the new latency target feels truly instant) is inherently a by-ear/by-eye call better made in an interactive session than confirmed here; the pipeline (device opens, correct triggers, no crashes) is confirmed working end to end, not fully fine-tuned live.
11. **[DONE, unseen live] Optional bitmap texturing** — Player-supplied `.bmp` textures for walls/floor/ceiling/entity sprites, added per explicit request as an opt-in exception to this project's otherwise-procedural, no-external-assets rule (see DESIGN.md's Graphics section and `assets/README.md`).
    - New `src/textures.ads/.adb`: one `Slot` per texturable surface (`Infantry_Tex`, `At_Gun_Tex`, `Wall_1_Tex` .. `Wall_3_Tex` matching `World_Map.Cell_Value`, `Floor_Tex`, `Ceiling_Tex`). `Load_All` looks for a fixed filename per slot under `assets/` at startup; anything missing, unreadable, or larger than a 512x512 cap just leaves that slot `Loaded = False`, so the game is byte-for-byte unchanged in appearance with no `assets/` folder at all. `Sample`/`Texel` wrap or clamp lookups for the floor-cast (unbounded world UV) and wall/sprite (bounded pixel-index) cases respectively.
    - `src/sdl2_thin.ads` gained `SDL_RWFromFile`/`SDL_LoadBMP_RW`/`SDL_ConvertSurfaceFormat`/`SDL_FreeSurface` and a `Surface_Header` record mirroring `SDL_Surface`'s leading fields (verified against libsdl2-dev 2.32.4's `SDL_surface.h`, same rigor as the existing `Audio_Spec`/`Event_Bytes` bindings) -- deliberately BMP-only via SDL2's own built-in loader rather than adding an SDL2_image dependency; `SDL_LoadBMP` itself is just a header macro over the two RWops/surface calls, reimplemented here since GNAT can't import a C macro directly. Every loaded surface is normalized to `ARGB8888` via `SDL_ConvertSurfaceFormat` so the renderer never needs to handle per-file source pixel formats (24-bit BGR, paletted, etc.) itself.
    - `src/raycaster.adb`: walls now sample their slot's texture (when loaded) for both U (wall-hit fractional position, with the existing mirror-direction correction) and V (using the *unclipped* wall height so close-up walls that run off-screen still sample the right rows), still darkened on Y-side hits via a new `Shade` helper so the existing depth cue survives texturing. Floor and ceiling gained a genuine per-pixel perspective cast (Lodev-style: row distance from screen Y and a `Pos_Z = H/2` camera-height constant consistent with the existing `Line_Height` math, folding in `Horizon_Shift` so it stays aligned under gun-sight pitch) rather than a flat fill -- this is new math, not a recolor, since the raycaster previously only drew flat sky/ground bands outside the wall silhouette. Entity sprites sample per-pixel instead of one solid color per column, and treat a texture's top-left pixel color as a transparency key so a sprite can be a cutout rather than a rectangle.
    - `src/main.adb` calls `Textures.Load_All` once at startup, after `Audio.Init` and before the event loop; no `Game_Phase` or per-frame changes needed since `Render`/`Render_Entities`'s existing signatures already carried everything required (camera pose, entity list) to add texturing internally.
    - Verified via a clean `gprbuild -P tankette.gpr -f -p` (no warnings under `-gnatwa`) and an end-to-end WSLg smoke run with three throwaway generated `.bmp` files (a wall, a floor tile, a sprite with a colorkey background) dropped into `assets/`: the game launched, ran for the full test window with no crash/error output, and was confirmed separately to behave identically with `assets/` empty. As with milestones 8/9, this ran as a background job with no screenshot tool available in the WSL environment to capture the live window -- so unlike the pipeline (loads, falls back correctly, no crashes), the actual on-screen texture mapping (UV orientation, floor-cast alignment under pitch, sprite cutout edges) has not been eyeballed live and is worth a real play-through with real art before calling this fully settled.
12. **[DONE] Clutch-brake steering levers** — Replaced the binary Q/E track-declutch model with a real T-34-style 3-position lever per track (Drive/Declutched/Brake), so the two levers' *combination* produces qualitatively different turning and speed-loss behavior instead of a single flat effect.
    - `src/hull.ads/.adb`: `Hull.State` gained persistent `Left_Speed`/`Right_Speed` fields (previously each track's speed was recomputed from scratch every frame with no memory between frames, so nothing could ramp or decay). New `Lever_Position` type (`Drive`/`Declutched`/`Brake`) replaces the old `Left_Declutched`/`Right_Declutched` booleans in `Hull.Update`. Each track now eases toward a target every frame (`Track_Speed`): Drive eases toward the throttle-derived speed (`Accel_Rate`), Declutched holds steady (no clutch drag of its own), Brake eases toward zero fast (`Brake_Rate`); a small always-on `Rolling_Friction` decay then applies to all three alike, modeling the vehicle's own ground/mechanical drag independently of the clutch -- this is what makes "Declutched" both literally true to "no resistance" from the clutch *and* still gradually lose speed. Differential-drive kinematics (`Linear_Speed`/`Angular_Speed`) and the wall-slide collision are unchanged, just fed from the new persistent speeds.
    - Controls: absolute-position, sticky (latching) number keys instead of held-key declutch -- left track **1**/**2**/**3** = Drive/Declutched/Brake, right track **0**/**9**/**8** = Drive/Declutched/Brake (deliberately inverted from the left track's order, per feedback) (`src/sdl2_thin.ads` gained `SDLK_8`/`SDLK_9`; `SC_Q`/`SC_E`, now unused, were removed). Levers are set edge-triggered in the event loop (same pattern as the Z/X toggles) rather than read as frame-polled held state, since a real lever stays where you put it; `main.adb` carries `Left_Lever`/`Right_Lever` as persistent state, defaulting to Drive/Drive. Space/C throttle is unchanged -- the levers decide whether a track follows it, not whether the tank moves at all.
    - `Audio.Track_Strain` (engine-grind cue) re-scoped from "either track not in Drive" to "either track in Brake specifically" under throttle -- a plain Declutched track under power is silent freewheeling now, not a grind.
    - Added per this feature's own need (sticky keys give no physical feedback of current lever state, unlike the old held-key model): `Hud.Draw` gained two small 3-pip columns (`Draw_Lever_Pips`, same visual language as `Draw_Hit_Pips`) next to the hull icon, one per track, highlighting its current lever position; plus a bottom-right legend (`Draw_Lever_Legend`/`Draw_Lever_Icon`) -- a small vertical 3-stop icon per track (top=Drive, middle=Declutched, bottom=Brake, mirroring a real lever's travel) next to a "D DRIVE / C CLUTCH / B BRAKE" text key, added per feedback since the header pips alone don't explain what the positions mean. `Hud`'s letter font gained B/K/V for "BRAKE"/"CLUTCH"/"DRIVE".
    - Verification pending a live interactive session (this was authored as a background job): confirm the clean `gprbuild -P tankette.gpr -f -p` build, then in `Playing`, exercise all nine lever combinations against the described feel (gentle vs. sharp turn, slow coast vs. hard stop, brake holding against throttle) and check both the header pips and the new bottom-right legend track key presses correctly.
    - Amended per feedback: Drive no longer eases toward a fixed `Engine_Speed` target (an artificial governor reached almost instantly at the old `Accel_Rate`). `hull.adb`'s `Track_Speed` now adds a small constant `Accel_Increment` to a Drive track every frame the throttle is held, instead of easing toward a capped target -- `Accel_Rate` and the old `Engine_Speed` constant are both gone. There is no top-speed constant left in the module at all: the only thing opposing acceleration is the existing `Rolling_Friction` drag, so speed keeps climbing for as long as you hold the throttle and only settles at a natural equilibrium (`Accel_Increment * (1 - Rolling_Friction) / Rolling_Friction`) rather than hitting a hardcoded ceiling -- a real straightaway now rewards patience with genuinely higher speed instead of governing out after a fraction of a second.
